# Experimental bounded socket I/O

This opt-in experiment repairs incomplete socket writes and cyclic backpressure
in the helper and broker. It builds a separate executable from the pinned public
source. It does not modify `slmbridge.c`, `slmbridge_rstest.c`, the normal build,
or any service. Physical modem rates, dropped-call percentages and payload
throughput have not been measured for this candidate.

The experiment is based on public main commit
`309d3a9809179d5d331d5adbd7dea7275200ed80`. Both standalone remotes had that same
commit when this branch was prepared. The source SHA-256 is
`9ddc2eae070d5082b59d67d7f955fd8979485e03f775ca9cdee2d16da3af6308`.
The transformation must produce reviewed candidate source SHA-256
`d354ab6a4ef5dd9a5685a80682ee05cfdb989274b2c0a6f07b877d311939597b`.
The builder rejects source or transformation drift. It also requires regular
source/fixture files, hashes them before and after the run, verifies copied and
generated sources, and records whether all inputs remained unchanged. Each
compiler or test command has a 90-second deadline. The test fixtures explicitly
pin their public helper controls so ambient settings cannot select an arm.

## Build and validate

Requires Linux, GCC, Python 3, pthread and libm. From the repository root:

```sh
python3 experiments/stream-io/build.py --output /tmp/slmbridge-stream-io-build
```

Use a new output directory for each run. `--source /path/to/slmbridge.c` can
select another copy of the exact pinned public source. The builder compiles a
pristine executable and the candidate, runs the component and actual-function
socket tests, then writes `manifest.json` in the output directory. It does not
run the bridge's main entry point, open a listener or TTY, start a modem, or
change a service. Tests use generated bytes, local AF_UNIX socketpairs and
children they create themselves. Full integration requires Linux socket
readiness semantics.

The generated `bridge.c` is self-contained: the transform inlines the transport
header. This experiment does not add a header dependency to the normal public
source or its existing two-file extraction workflow. `make` continues to build
the original main source; it does not select this experiment.

The candidate accepts the existing command-line arguments. The new variable
`SLMBRIDGE_STREAM_IO` controls its socket path:

| Value | Behavior |
|---|---|
| Unset or exactly `0` | Original helper and broker functions, with the opt-in check |
| Exactly `1` | Bounded stream path described below |
| Anything else | Visible configuration error before main opens sockets or TTYs |

Both the broker and its helper need the selected setting. A same-binary off/on
comparison avoids changing unrelated compiler or source inputs. Original
helper, broker and resampler source preservation is asserted by the tests;
this is not a claim that an arbitrary deployed binary matches this source.

## What changes

The original helper sets its PCM socket nonblocking, then ignores both forms
of AS-to-PCM `write` result. Short writes, EINTR and EAGAIN can discard bytes
while the receive-frame counter advances. Its outgoing AudioSocket frame uses
one write; a short/error write terminates without completing the suffix. The
broker retries positive short writes but blocks inside one direction, delaying
reverse traffic and its TTY/busy-connection watch.

The candidate preserves accepted byte prefixes and retries only the remaining
suffix. `MSG_DONTWAIT | MSG_NOSIGNAL` keeps socket operations nonblocking without
changing descriptor flags. EINTR and EAGAIN return to the existing poll loop;
POLLOUT resumes pending writes. Zero or irrecoverable results fail visibly.
Queues never evict bytes or grow dynamically:

| Queue | Bound |
|---|---:|
| Helper PCM input FIFO | 256 KiB |
| Helper outgoing AudioSocket data | One 323-byte frame |
| Broker, each direction | One batch of at most 8,192 bytes |

The helper reserves enough free PCM space for the largest converted AUDIO
batch before accepting another TLV: at most 9,832 bytes at 9.6 kHz or 8,192
at 8 kHz. Appends preserve order; compaction moves only the unconsumed suffix.
The broker withholds further reads in a direction until its preceding batch
drains. Half-closes propagate after the corresponding accepted bytes drain.

TLV parsing is incremental, takes one complete message per iteration and never
reads into the next message. AUDIO must have a nonzero, even payload no larger
than 8,192 bytes. Invalid lengths and truncated EOF fail explicitly. Other
traffic can progress while a TLV arrives in fragments; previously `read_exact`
blocked all work during that interval.

The existing resampler functions, filter profiles, prefill, ring-frame choice,
optional sample-slip policy and underrun fill are retained. PCM reads account
for the actual resampler phase and a carried odd byte, so converted output fits
the ring. A full ring applies backpressure instead of reading PCM into a discard
buffer. No extra samples or TX clock credits are introduced to clear a stall.

## Pacing and finite limits

In RX-clock mode, each real received AUDIO TLV earns the existing one-frame TX
credit even if some corresponding PCM bytes are still queued. This lets the
ring drain while a synchronous peer finishes its output before reading more
input. Further complete AUDIO frames can enter the bounded FIFO and earn their
own credits; a pending outgoing AS frame stops new AS input.

The existing one-TX-frame-per-TLV rule is retained for all accepted even AUDIO
sizes. Repeated maximum-size payloads therefore do not have balanced input and
output sample counts. The FIFO does **not** guarantee universal progress for
such framing or arbitrary peer behavior.

A current output block is not the whole cyclic-stall bound. In an isolated
Linux fixture, default AF_UNIX send buffers accepted 180,224 payload bytes and
required 139,520 bytes to drain before POLLOUT woke the producer. Normal
320-byte AUDIO at 20 ms intervals cleared this deliberately full two-direction
state within the fixed FIFO. Maximum-size frames can fill it and reach explicit
containment instead. See [validation](VALIDATION.md) for the measured cases.

Timer mode retains its deadline when only PCM input is pending. When AS output
is queued, the next timer deadline advances only after the complete frame is
accepted, matching the old blocking write and preventing an extra frame on
resume. A fragmented TLV or pending AS frame suspends the timer as before.
Internally queued PCM does not earn synthetic 200 ms RX fallback credits; the
existing unblocked fallback behavior remains.

In the helper, two seconds without useful stream progress causes an explicit
`ETIMEDOUT`. The broker retains its separate 30-second poll inactivity timeout.
Actual incoming AS bytes, reverse PCM bytes and accepted PCM writes reset this
watchdog. Accepted AS writes also count when RX-clocked or when no PCM FIFO is
pending. Timer-generated filler alone cannot keep a stuck PCM direction alive.
A legitimate many-second reverse-draining cycle therefore continues while
making progress; elapsed time without a PCM write alone is not a timeout.

## Evidence and interpretation

Enabled helper and broker exits add:

```text
bridge_stream_io: role=helper|broker enabled=1 error=N reason=... to_first_pending=N to_second_pending=N partial_input=N to_first_bytes=N to_second_bytes=N short_writes=N waits=N interrupts=N
```

For the helper, first means AudioSocket and second means PCM. For the broker,
first means its caller socket and second means its helper socket. A nonzero
error or retained suffix is not successful delivery. An invalid flag prints
`INSTRUMENT ERROR`; actual protocol/transport failures remain separate.
The off path prints no new summary. Existing signal handling remains: forced
termination can omit a summary, so a missing line is unknown rather than proof
of delivery. Zero pending bytes at exit is not a FIFO high-water measurement.

The tests cover byte fragments, short/EINTR/EAGAIN/zero/fatal writes, fixed FIFO
compaction and capacity, all TLV split positions and truncated EOFs, actual
resampler phase counts, source preservation, actual helper/broker byte streams,
paced full-buffer cycles and timer behavior after a stall. The published
validation is a sanitized summary. Raw local build manifests should be reviewed
before sharing because they contain compiler/test diagnostics.

This experiment repairs transport accounting and bounded progress. It does not
change the DSP, noise/echo conditioning, modulation selection, answer command
formatting, or independently establish improved modem negotiation or uptime.
